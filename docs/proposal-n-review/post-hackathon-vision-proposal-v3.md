# EXTRA 개인 프로젝트 기획 v3

상태: 사용자 합의 반영 + 구현 전 검토 초안. v1은 비전 이력, v2는 이전 초안으로 보존한다.
이번 산출물은 문서이며 게임 코드 구현·유료 서비스 가입을 뜻하지 않는다.

## 1. 한 문장과 목적

이름 없는 인물에게 빙의해 역사 속 갈등을 겪고, 직접 말하거나 습득한 논거를 카드로 꺼내 쓰며, 그 경험을 수집해 실제 장소까지 찾아가는 게임.

핵심은 역사 인물을 이해한 나의 경험을 수집하는 것. 역사 지식 암기나 카드 전투만이 목적은 아니다. 왜 그 사람이 그런 결정을 했는지, 반대편은 무엇을 우려했는지 이해하게 한다.

## 2. 합의한 방향

- NHN 해커톤은 종료. 이후는 개인 프로젝트. 출품 경계는 hackathon-submission 태그.
- 첫 이야기: 훈민정음, 1444. 정확한 역사 장면·날짜·인물별 발언은 사료 검증 후 확정.
- 첫 목표: 스토리 하나 안에 미니게임, 실시간 멀티, 카드 사용/대결을 연결.
- 대상 우선순위: 역사에 익숙하지 않은 성인 및 참여형 게임 이용자, 중·고등학생, 가족, 초등학생. 성인 공동 탐방·데이트도 고려.
- 타임슬립 드라마풍을 기본으로 인물 간 자연스러운 유머를 섞음. 세 가지 분위기 모드는 나중 확장.
- 내 아바타의 정체성은 유지하되 사건마다 당시의 이름 없는 역할에 빙의.
- 수호자/교란자는 가상 시간여행 참여자의 역할. 실존 반대파를 시간 교란자나 악당으로 만들지 않음.
- 카드의 시작점은 반복 타이핑 부담 해소. 카드 사용을 열등한 입력 방식으로 취급하지 않음.
- 직접 쓴 변론도 사람 간 승패에 영향. 경기 후 습득·성장 보상도 존재.
- NPC와 함께 기본, 독대 선택 가능. NPC임을 명확히 표시.
- 초기 최대 동시 접속 테스트 목표 20명. 사람이 없더라도 진행 가능.
- 실용형 AI 운영부터 시작. 필요한 장면만 상위 모델로 교체 가능한 구조.
- 음성 입력은 녹음 → 텍스트 확인·수정 → 제출. 주요 대사는 사전 제작 음성.
- 유료화는 외형 중심, 결제 결정·구현은 나중. 거래는 게임머니 중심이며 가격 상한 필요.
- 게임에서 장소 정보 카드 획득. 현장에서는 공동 탐방 퀘스트·도장·외형 보상. 방문 여부로 전투력 차이를 주지 않음.
- 개발 방식: AI와 협업. 사용자 투입 약 주 35시간(기획·실행·리뷰 포함), 다른 프로젝트도 병행.

## 3. v2에서 폐기·수정하는 부분

1. 카드 80% 효율 페널티 폐기. 같은 논거는 입력 방식과 무관하게 같은 기본 효과.
2. AI가 직접 변론을 해석하므로 PvP 전체가 결정론적이라는 주장 폐기. 효과 계산만 결정론적이다.
3. temperature=0이 공정성과 재현성을 보장한다는 가정 폐기.
4. 경기 패배와 발언 오류 분리. 패배한 플레이어도 타당한 논거 카드를 얻는다.
5. 의도적 오류에 강한 공격 카드를 주는 구조 폐기. 타당한 반대 논거는 정상적인 강한 카드가 될 수 있다.
6. 오답 수집보다 정정·통찰 성장 중심. 확인되지 않는 추론과 사실 오류를 구분.
7. 최만리 등 역사 인물은 상대편 슬롯의 시간여행 NPC가 아님.
8. UI 발언 중복·도감 비표시는 재현 필요한 관찰 사항. 코드 원인 확인 전 버그로 단정하지 않음. 실제 AI 호출/폴백 여부도 로그로 확인 필요.
9. 6인 방, 15초 매칭, 60초 5라운드, 가격 상한 2배, 24시간 거래 제한 등 v2 수치는 미확정 제안.
10. 15~19주 일정은 폐기. 실제 개발 속도와 검증 결과를 보고 추정한다.
11. 새 카드는 직접 변론에서만 나온다는 절대 규칙 폐기. 스토리·미니게임·직접 변론 등 여러 획득 경로를 유지.

## 4. 이야기와 캐릭터

### 역사 인물
- 세종: 이미 의지와 전문성을 가진 결정권자. 플레이어의 칭찬 몇 마디로 창제 의지가 생기는 인물로 그리지 않는다.
- 최만리: 당대 질서·학문 등의 관점에서 반대 논리를 가진 역사 인물. 희화화하지 않는다.
- 나머지 실존 인물: 해당 장면 참여와 발언을 검증한 뒤 배치.
- 논쟁 게이지는 인물의 실제 속마음 수치가 아니라 가상 장면 내 논쟁의 우세를 표현.

### 가상 인물
- 빙의 역할 후보: 문서 전달을 돕는 이름 없는 하급 실무자. 직책·궁궐 출입·논쟁 참여 경위는 고증 전 가설.
- 생활 인물: 문서를 남에게 의존하면서 자기 사정이 정확하게 전달되는지 불안해하는 사람. 창작 인물·사건임을 명시.
- 동료: 상황과 조작을 알려주되 정답만 말해주는 안내판으로 만들지 않음.
- 대체 플레이어 NPC: 근거형·공감형·질서형 등의 전략 성향. 규칙으로 카드를 선택하고 준비된 대사를 사용.

캐릭터 시트 필수 항목: 사실/창작 구분, 목표, 우려, 지식 범위, 양보 가능 지점, 출처, 말투, 감정 표현 범위.
미술: 일관된 2D 인물 + 표정 4~6종을 초기 후보로 한다. 턴마다 이미지 생성하지 않는다.

## 5. 핵심 루프

빙의·정체 파악 → 생활 사건 경험 → 조사 미니게임 → 논거 습득 → 갈등 장면에서 직접 발언/카드 사용 → 가상 결과와 실제 역사 비교 → 개인 카드·성장 보상 → 재도전·다른 진영·관련 장소 탐방.

한 번의 승패가 실제 역사의 옳고 그름을 판정하지 않는다. 교란 성공은 가상 분기이며 실제 역사와 명확하게 분리한다. 글로벌 영구 역사 변경·다른 유저 복구는 후속 후보이고 첫 구현 필수 아님.

## 6. 자유 변론과 카드가 만나는 규칙

### 공통 처리
1. 카드: 검증된 논거 ID + 행동 유형 + 대응 논점으로 제출.
2. 직접 입력: AI가 논거 후보·대응 대상·근거 상태를 구조화해서 제안.
3. 플레이어는 제출 전 짧은 해석 요약을 확인하거나 논점을 보정할 수 있음. 대기시간과 확인 단계의 부담은 테스트.
4. 서버는 허용된 행동과 사료 ID인지 검증.
5. 동일한 규칙 엔진이 비용·상성·반복 감쇠·효과를 계산.
6. 개인 발언의 카드 습득/성장은 경기 후 별도 처리.

AI는 공격력이나 사료 ID를 임의 생성하지 않는다. 허용 목록 밖 ID는 거부하고 재검토한다.
정확히 같은 논거·맥락이면 직접 입력과 카드의 기본 효과는 같음. 새로운 근거·적절한 적용이 성장 보상 기준.
같은 주장의 무한 반복은 입력 방식 모두에 동일하게 제한. 경기 중 반복 제한과 계정 성장 제한은 별개.

### 공정성·안전
- AI 해석이 승패에 영향을 준다는 점을 인정하고 초기에는 캐주얼 대전으로 검증.
- 낮은 확신은 오답 처벌 대신 선택형 보정·재검토로 처리. AI가 자기 확신 점수를 높게 냈다는 이유만으로 신뢰하지 않음.
- 사실 확인/사료 정합성과 논리적 관련성을 별도 평가.
- 사용자 발언은 비신뢰 데이터. 판정 지시문으로 취급하지 않으며 출력 스키마·허용 목록 검증.
- 제출 ID로 중복 행동과 중복 보상 방지. 규칙·콘텐츠·모델/프롬프트 버전 기록.
- AI 타임아웃 때 명확하게 안내하고 카드/기본 행동으로 전환 기회 제공. 복구 불가능한 장애의 패배 처리 금지.
- 상대 비공개 패나 숨은 상태를 AI 입력/클라이언트에 불필요하게 전달하지 않음.

### 오류와 페널티
- 첫 사실 오류/시대착오: 효과 없음 + 근거와 수정 기회.
- 확인되지 않은 추론: 추론 표시, 자동 오답 아님.
- 무관한 주장: 해당 논점 효과 없음, 복귀 안내.
- 정정 후 반복 오류: 사전에 공개된 경기 내 자원 감점 후보.
- 출처 조작: 검증 전 근거 무효. 반복 악용은 기록·검토.
- AI가 고의성을 추측해 계정 제재하거나 소유 카드를 몰수하지 않음.
- 오류를 수정하고 이유를 이해하면 통찰 보상. 쉬운 오답을 반복 생성해 보상을 얻는 파밍 제한 필요.

## 7. 카드와 신규 능력 승인

카드 원형: 고정 효과·논거·비용·상성·출처.
개인 카드: 원형 ID + 내 문장 + 획득 사건 + 숙련 기록 + 외형.

능력 성장과 수집 희귀도는 동일한 축으로 고정하지 않는다. 초보와 숙련자의 대전에는 제공 덱/비용 제한 등 검증 필요.
기존 카드와 표현만 다르면 새로운 능력이 아니라 개인화된 카드로 발급.

신규 능력 절차:
1. 개인 보상은 기존 허용 범위로 즉시 지급.
2. 플레이어 동의 시 새 논거 후보 제출.
3. 중복·개인정보·출처 확인.
4. 실험 모드에서 사용, 정식 거래·경쟁전 제외.
5. 커뮤니티는 재미·이해도 평가. 역사 타당성은 출처 검토, 밸런스는 테스트.
6. 운영자 승인 후 정식 카드 원형 추가. 동의한 최초 제안자에게 표시/외형 보상.

초기에는 운영자 검토만으로 시작. 투표만으로 정식 카드 승인하지 않는다.
개인 문장 공개는 선택, 공개 전 개인정보·욕설 처리. AI가 다듬은 문장과 실제 입력 기록도 구분한다.

## 8. 장소·거래·콘텐츠 출처

장소 정보 카드는 게임에서 획득. 사건 발생지/유물 소장처/현재 기념·전시장 구분.
현장 방문: 탐방 도장, 지도 기록, 외형, 후일담. 전투력 보상 없음.
공동 퀘스트: 동료끼리 서로 다른 단서를 확인해 답을 맞춤. 데이트·친구·가족 모두 가능.
허용된 동선에서 수행, 유물 접촉·출입 제한 구역 유도 금지. 실제 개방 여부 확인.
위치는 최소한으로 처리하고 동의 필요. 체크인 방식·원본 위치 보관 기간은 구현 전 결정.

거래는 후속 단계. 게임머니 가격 상한 취지 유지, 수치는 미확정. 가격 상한만으로 외부 거래·부계정 이전이 방지되는 것은 아님.
카드 소유권·잔액 변경은 원자적 서버 처리. 거래 이력·게임머니 소모처·중복 발급 방지 필요.
현금 구매형 재화로 전투 카드를 우회 구매시키지 않는 설계를 기본 제안으로 둔다.

역사 유튜브·인플루언서 자료는 접근성·설명 방식 참고. 공통 원출처 추적, 사실은 사료·연구로 확인.
대본·영상·그림·음성·페르소나 직접 사용은 권리 확인 및 허락. 향후 정식 협업 가능.
게임 내 직접 인용/현대어 재구성/창작을 구분. 출처가 있다는 이유만으로 심리·인과까지 확정하지 않음.

## 9. 기술 구성: 제안과 확정의 구분

확정 방향: 웹 2D, 서버 권위 판정, 초기 최대 20명, 모델 교체 가능한 실용형 AI.
도구 후보(아직 도입하지 않음): Vite + TypeScript + React, Node + Colyseus, Supabase Auth/Postgres, Vitest/Playwright.
React와 Svelte는 짧은 카드 UI 실험·유지보수 난도를 보고 하나만 선택. 프레임워크 전환 자체를 목표로 삼지 않음.
현행 콘텐츠·사료·이미지는 재사용, app.js 기능은 인벤토리와 테스트 후 분리. 기존 역방향 엔진의 재사용 가능성은 코드 검토 필요.

경계:
- content: 장면·인물·사료·논거·카드 원형
- rules: 순수 함수, 효과 계산 및 반복 제한
- rooms: 참가·타이머·비공개 패·재접속·NPC 대체
- ai: 변론 해석/대사/카드 심사 어댑터
- persistence: 진행·카드·경기 결과·보상 원장
- ui: 스토리/입력/대결/카드첩/결과

첫 멀티 실험은 2대2 후보. 20명=5개 방으로 부하 검증. 독대 20개 방처럼 AI 호출 수가 증가하는 상황도 테스트.
사람이 NPC 자리를 이어받는 기능은 초기 필수 아님. 우선 방 시작 시 구성 확정 + 연결 끊김 시 대체/재접속부터.
게스트 localStorage 기록은 서버 발급 카드·재화로 무검증 이관하지 않음.
다중 지역·복잡한 자동확장·마이크로서비스는 제외.

## 10. 비용과 운영

최대 동시 20명은 월 이용량이 아님. 비용은 실제 플레이 횟수·카드 사용률·자유 변론 횟수·토큰·음성 분량으로 측정.
이전 대화의 15분당 약 15원(실용)/75원(균형)은 가정치, 보장 가격 아님. 예: 월 500회라면 AI 약 7,500원/37,500원, 서버·음성·세금·제작·개발 도구 별도.
월 10만원은 초기 운영 경고선 제안이며 공급자 청구 상한이나 서비스 가입 승인 아님.
서버 측 토큰/호출 한도, 사용자 속도 제한, 비용 알림, 이상 사용 차단 필요. AI를 생략할 경우 사용자에게 알리고 준비된 대사/카드 규칙으로 진행.
카드는 해석 호출 생략, 방 공통 대사는 한 번 생성, 사료 검색·요약은 문맥 길이 제한.
캐시 키에 장면·규칙·논거·맥락 버전 포함, 다른 맥락의 판정 재사용 금지.
음성: 녹음 → 전사 확인 → 제출. 원음 저장 여부·삭제 정책 필요. 주요 NPC 음성은 사전 제작.

## 11. 구현 순서와 검증 관문

A. 현재 기능/사료 검토 + 첫 10분 스토리 초안. 라이브 AI/폴백 관측과 UI 문제 재현.
B. 조기 기술 실험: 두 브라우저가 한 방에서 카드 1장 제출, 중복·연결 끊김 처리. 동시에 자유 발언 30~50개 해석 평가.
C. 빙의 → 생활 사건 → 조사 → 첫 논쟁 → 카드 습득의 작은 완결 경험.
D. 이를 NPC 동반/사람 동반 양쪽으로 연결. 규칙과 타이핑/카드 등가성 테스트.
E. 20명 부하, 음성 입력, 서버 발급 카드 저장, 작은 초대 테스트.
F. 결과를 보고 이야기·카드 확대. 거래/공동 탐방/승인 커뮤니티는 후속.

날짜 약속 대신 검증 관문을 사용. 사용자 주 35시간 중 고증·리뷰·테스트 시간을 반드시 확보.
첫 사용자 테스트 질문: 인물이 왜 반대/찬성했는지 자기 말로 설명하는가? 카드를 다시 쓸 이유를 아는가? 반대편으로 다시 해보고 싶은가? 관련 장소가 궁금해졌는가?
첫 테스트 제안 목표: 5명 중 4명 이상이 카드 사용을 도움 없이 수행하고, 3명 이상이 양측의 이유를 각각 하나 설명. 학습효과 입증이 아닌 초기 사용성 신호.
AI 평가에는 같은 뜻 다른 표현, 올바른 반대 논거, 시대착오, 불확실한 추론, 가짜 출처, 프롬프트 공격, 음성 오인식 포함.
