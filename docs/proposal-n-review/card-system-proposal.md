# 반박 카드 수집 · 덱빌딩 시스템 제안

> **제안일:** 2026-08-09
> **제안자:** 정윤
> **상태:** 제안됨 (Proposed)

## 1. 배경 / 문제의식

현재 반박 모드는 매 라운드 같은 논점에 대해 플레이어가 매번 손으로 반박을
새로 작성해야 한다. 반복 플레이 시 "같은 말을 계속 손으로 치는 피로"가 크고,
플레이어가 쌓아온 좋은 반박이 1회성으로 소모되어 성장·수집의 재미가 없다.

## 2. 핵심 아이디어

플레이어가 작성해 **성공한 반박을 "카드"로 저장**하고, 이후 라운드에서
그 카드를 꺼내 재사용할 수 있게 한다.

- 이지에서 얻은 카드는 이지에서도, 상위 난이도에서도 사용 가능하다.
- 단, 상위 난이도에서는 같은 카드가 **부분적으로만** 통하도록 감쇠시켜
  "카드 + 손 보강" 조합 플레이를 유도한다.
- 카드에는 등급(브론즈~골드)이 붙고, 더 좋은 반박을 쓰면 카드가 성장한다.
- 논점 태그로 카드를 분류해 "덱 구성"이라는 새 재미를 만든다.

**우선순위: 수집 · 덱빌딩(새 재미) > 손으로 반복 입력 피로 감소(편의).**

## 3. 게임 규칙

### 3.1 카드 획득
- 라운드에서 특정 논점에 대한 반박이 성공(합격선 이상)하면 해당 논점 ID로
  카드가 생성/갱신된다.
- 이미 같은 논점 카드가 있으면, **더 높은 점수의 반박으로만** 덮어쓴다
  (best-rebuttal 추적).

### 3.2 카드 등급
| 등급 | 조건(반박 점수 기준 예시) | 시각 |
|------|--------------------------|------|
| 브론즈 | 합격선~70 | 동색 테두리 |
| 실버 | 71~85 | 은색 테두리 |
| 골드 | 86~100 | 금색 테두리 + 이펙트 |

- 장기 목표: "모든 논점 골드 카드 수집".

### 3.3 카드 재사용 & 난이도 감쇠
- 라운드 진입 시, 등장 논점에 매칭되는 보유 카드가 있으면 "카드 사용" 가능.
- 심판(LLM)은 재사용 카드를 **더 엄격히** 평가한다.
  - 난이도가 카드 획득 난이도보다 높으면 감쇠 계수를 적용.
  - 예: 이지에서 얻은 골드 카드를 하드에서 쓰면 인정률 60% → 나머지는
    손으로 보강하거나 미야모토가 파생 논점으로 반격.

### 3.4 덱빌딩
- 카드는 논점 태그(#design, #commercial, #art 등)로 분류.
- 스테이지 진입 전, 플레이어가 카드를 덱에 편성(예: 최대 N장).
- 상대 논거에 맞는 태그의 카드를 고르는 전략적 선택이 발생.

### 3.5 밸런스 제약(치트 방지)
- 카드 사용 시 게이지 소량 소모 (손으로 새로 치면 게이지 소모 없음).
- 한 보드에서 사용 가능 카드 수 제한(예: 1~2장).
- 카드로만 클리어 시 랭크에 "카드 의존" 표시, 전부 손으로 클리어하면
  상위 등급 부여.

## 4. 데이터 구조

### 4.1 카드 (CardEntry)

```ts
interface CardEntry {
  cardId: string;          // 논점 ID 기반 (예: "miyamoto-art-01")
  argumentId: string;      // 대응하는 논점 ID
  character: string;       // 획득 인물 (예: "miyamoto")
  tags: string[];          // ["#art", "#commercial"]
  rebuttalText: string;    // 저장된 최고 반박 텍스트
  score: number;           // 획득 시 점수 (0~100)
  grade: "bronze" | "silver" | "gold";
  sourceDifficulty: "easy" | "normal" | "hard"; // 획득 난이도
  createdAt: number;
  updatedAt: number;
  useCount: number;        // 재사용 횟수 (통계/전당)
}
```

### 4.2 컬렉션 (플레이어 보유 카드 전체)

```ts
interface Collection {
  cards: Record<string, CardEntry>;   // key = cardId
  totalOwned: number;
  goldCount: number;                  // 골드 수집 진척도
}
```

### 4.3 덱 (라운드 편성)

```ts
interface Deck {
  stageId: string;
  cardIds: string[];       // 편성된 카드 (최대 N장)
  maxSlots: number;
}
```

### 4.4 심판 요청에 추가되는 필드 (재사용 시)

```ts
interface JudgeRequest {
  argumentId: string;
  rebuttalText: string;
  isReusedCard: boolean;        // 카드 재사용 여부
  cardSourceDifficulty?: string;// 카드 획득 난이도
  currentDifficulty: string;    // 현재 라운드 난이도
  // → 프롬프트: 재사용 카드이고 현재 난이도가 더 높으면 더 엄격히 평가
}
```

## 5. UI 흐름

### 5.1 라운드 중 (카드 사용)
1. 미야모토가 논점 제시.
2. 하단에 입력창 + "보유 카드" 버튼 노출.
3. "보유 카드" 클릭 → 해당 논점 태그에 매칭되는 카드 목록 표시
   (등급 테두리, 예상 인정률 미리보기).
4. 카드 선택 → 반박창에 자동 입력(수정 가능) → 제출.
5. 결과: 감쇠 적용된 판정 + "손으로 보강하시겠어요?" 프롬프트.

### 5.2 라운드 종료 (카드 획득/성장)
1. 승리 시 성공한 논점별로 카드 획득/갱신 연출.
2. "새 카드 획득!" 또는 "카드 등급 상승! (실버 → 골드)" 토스트.
3. 컬렉션 진척도 표시(예: 골드 7/20).

### 5.3 덱 편성 화면 (스테이지 진입 전)
1. 스테이지 선택 후 "덱 편성" 화면.
2. 좌측: 보유 카드 목록(태그 필터 가능).
3. 우측: 덱 슬롯(최대 N장). 드래그/클릭으로 편성.
4. 상대 인물의 논점 태그 힌트를 상단에 표시(전략적 편성 유도).
5. "출전" 버튼 → 라운드 시작.

### 5.4 컬렉션 화면 (도감)
1. 전체 논점 그리드(미획득은 실루엣/자물쇠).
2. 카드 클릭 → 저장된 반박 텍스트, 등급, 획득 난이도, 재사용 횟수 표시.
3. 상단에 수집률·골드 진척도 게이지.

## 6. 구현 우선순위 (해커톤)

1. **카드 저장/획득** — 성공한 반박을 논점 ID로 저장(rev 로그 활용, 저비용).
2. **카드 재사용 + 난이도 감쇠** — 심판 프롬프트에 감쇠 조건 추가.
3. **등급/성장 + 컬렉션 도감** — 수집 욕구 시각화.
4. **덱 편성 화면** — 덱빌딩 재미(시간 되는 만큼).

## 7. 열린 질문 / 결정 필요 사항

- 덱 슬롯 수(N)와 보드당 카드 사용 제한 수치.
- 상위 난이도 감쇠 계수(예: 60%)와 등급별 인정률 편차.
- 카드 사용 시 게이지 소모량.
- 컬렉션을 인물별로 분리할지, 전역 통합할지.
