## 1. 개요 & 범위

### 1.1 액터
| 액터 | 설명 |
|---|---|
| 플레이어(단역) | 링크로 즉시 진입, 로그인 없이 인물을 설득 |
| 심사자 | 플레이어와 동일 경로. 장애 시에도 데모 모드로 반드시 체험 가능해야 함 |
| 콘텐츠 관리자 | `agents/`·`docs/research/` 사료 큐레이션(런타임 아님) |

### 1.2 용어
- **인물(에이전트):** `agents/<id>` 파일 하나 = 인물 하나.
- **숨은 조건:** 인물별 `통하는_가치`. 플레이어에게 비공개.
- **부합도:** AI가 내는 5단계 등급(탁월/정합/부분/불합치/역효과). 엔진이 수치로 변환.
- **신념 게이지:** 승리까지의 진척도. 0~100.
- **사료 조각:** RAG 저장소 단위(id·원문·출처·티어).

### 1.3 데모 범위(In) / 제외(Out)
- **In:** 세종 1인 풀 플레이, 설득 루프, 메커니즘 A/B/C/D, 결과 카드/공유, 정통·밈 토글, 조작 방어, 폴백.
- **Out(확장):** 검투사·호쿠사이 풀 플레이(스키마·스크린샷만), GPS, 멀티플레이, UGC, 계정.

## 2. 시스템 구성

```
web(프론트) ──HTTPS──> server(서버리스 프록시)
  │ 화면·엔진·표시            │ 하네스: 정규화·조작탐지·RAG·프롬프트·검증
  │                          │ ├─> Claude(판정·대사)   [턴당 1회]
  │                          │ └─> fallback(데모 응답 풀)
  └ engine/: 게이지·턴·승패·등급 (결정론)
데이터: agents/<id>, config/difficulty.json, config/memes.json, docs/research/
```

## 3. 화면 명세

| ID | 화면 | 목적 | 핵심 구성요소 | 전이 |
|---|---|---|---|---|
| SCR-01 | 지도 | 유적 선택 | 지도, 유적 핀(경복궁), (확장)잠금 핀 | 핀 선택 → SCR-02 |
| SCR-02 | 소환 | 인물 등장·도입 | 유물 연출, 인물 초상, 도입 대사(첫 힌트), 정통/밈 토글 | 자동 → SCR-03 |
| SCR-03 | 대화 | 설득 루프 | 신념 게이지 바, 턴 카운터, 대화 로그, 입력창, **출처 각주 토글**, 톤 토글 | 승리/패배 → SCR-04 |
| SCR-04 | 결말 | 승/패 연출 | 승리(뜻을 굳힘)/패배(하옥 등) 연출, 해설 팝업(교육) | → SCR-05 |
| SCR-05 | 결과 카드 | 공유·도전 | 카드(내 문장·턴·등급), 공유 버튼, 도전장 링크, 다시하기 | 링크 → SCR-01 |

**SCR-03 상세 상태:** `입력대기 → 판정중(로딩) → 결과반영(게이지 애니메이션·대사·각주) → 입력대기` 루프.
막힘(연속 실패 3회) 시 힌트/사료 언락 배지 노출. 모바일 세로 우선, 대화 로그 스크롤.

## 4. 기능 명세

> 표기: 입력 → 처리 → 출력 / 예외. **수용기준(AC)** 은 데모 통과 조건.

### FN-01 유적 선택
- 입력: 지도에서 유적 핀 탭 → 처리: 인물 id 결정, 세션 생성 → 출력: SCR-02 전이.
- AC: 경복궁 선택 시 세종 세션이 생성된다.

### FN-02 인물 소환
- 처리: `agents/<id>` 로드, `config/difficulty.json`의 인물 상수로 게이지 초기화 → 출력: 도입 대사(첫 힌트 포함).
- AC: 세종 진입 시 게이지=초기값(40), 도입 대사에 실용성 힌트("중국의 글이 있는데 무엇하러")가 포함된다.

### FN-03 논거 입력 & 턴 처리
- 입력: 자유 텍스트 → 처리: 정규화 → 조작탐지 → RAG → 판정(FN-04) → 엔진(FN-05) → 출력: 인물 대사 + 게이지 변화 + 턴+1.
- 예외: 빈 입력/과도한 길이 → 안내 후 반려(토큰 소모 0).
- AC: 한 번의 입력이 **AI 호출 정확히 1회**를 유발한다.

### FN-04 판정 (AI)
- 입력: 인물 스키마 발췌 + RAG 조각 + 히스토리 + 톤 + 발화 → 처리: Claude 호출(구조화 출력) → 출력: `Verdict`(§5).
- 예외: 스키마 위반 → 1회 재시도 → 실패 시 `불합치` 중립 대사.
- AC: 출력은 항상 `VERDICT_SCHEMA`를 만족한다(검증 통과).

### FN-05 게이지·승패 엔진 (결정론)
- 입력: `부합도` → 처리: `grade_to_points` 매핑·게이지 clamp(0~100)·턴+1·승패 판정 → 출력: 새 `GameState`.
- 규칙: 게이지 ≥ `win_threshold` → WIN / 연속 변사 ≥ 3 → LOSE / 그 외 CONTINUE.
- AC: **같은 입력 등급 → 항상 같은 게이지 결과**(재현성). AI가 수치를 바꿀 수 없다.

### FN-06 시대착오 감지 (메커니즘 A)
- 처리: 당대에 없는 개념(민주주의·표현의 자유 등) 탐지 → 인물이 못 알아듣는 연기 + `불합치/역효과`.
- AC: "표현의 자유니까요" 입력 시 세종이 못 알아듣고 게이지가 오르지 않는다.

### FN-07 재반박 부메랑 (메커니즘 B)
- 처리: 저장소의 반대 논리(예: 최만리 상소)로 인물이 되받음. **세종 침묵 논거(이적·형옥)** 는 강한 공략축.
- AC: 특정 논거에 대해 인물이 사료 기반 재반박 대사를 낸다(최소 1케이스).

### FN-08 출처 = 점수 (메커니즘 C)
- 처리: 논거가 매칭한 `사용_사료`가 강할수록 등급↑, 승리 해설에 사료 각주.
- AC: 승리 시 결과/해설에 최소 1개 사료 출처가 표시된다.

### FN-09 힌트 언락 (메커니즘 D)
- 처리: 연속 실패 3회 시 `config.hint_unlock.order`에 따라 실제 사료 1조각 노출(세종: S-02→S-04→S-03).
- AC: 3회 실패 후 실제 사료 힌트가 열린다.

### FN-10 "모르면 모른다"
- 처리: RAG 결과가 비면 인물이 환각 대신 "그건 기록에 없네"로 답(게이지 불변).
- AC: 저장소에 없는 사실 질문에 지어내지 않는다.

### FN-11 정통/밈 토글
- 처리: 톤 전환 시 **말투 층만** 변경(`config/memes.json`), 사실·사료·판정 불변. 기본값=정통.
- AC: 밈 모드에서도 사료 인용부에 유행어가 섞이지 않는다.

### FN-12 조작 시도 방어
- 처리: 인젝션("이전 지시 무시" 등) 비-AI 규칙 탐지 → 인물 정색 + 게이지 하락(차단 아님). AI 호출 없음.
- AC: 대표 인젝션 문구가 게임 내 연출로 전환되고 게이지가 하락한다.

### FN-13 결과 카드 & 공유
- 처리: 내 문장(1~2줄)·턴·등급·도전문구 카드 생성. **숨은 조건 미노출**. 공유 링크/도전장.
- AC: 카드에 숨은 조건이 노출되지 않는다.

### FN-14 폴백 / 데모 모드
- 처리: 상한/429/타임아웃 → 사전 생성 응답 풀. 완전 장애 → 스크립트 데모(고정 승리 루트).
- AC: API 차단 상태에서도 심사자가 게임을 끝까지 체험할 수 있다.

## 5. 데이터 모델

```ts
GameState {
  sessionId: string
  agentId: "sejong" | ...
  gauge: number          // 0~100
  winThreshold: number
  turn: number
  consecutiveFail: number
  status: "CONTINUE" | "WIN" | "LOSE"
  history: Turn[]
  tone: "정통" | "밈"
}

Agent {                  // agents/<id>
  id; 이름; 유적; 난이도
  통하는_가치: Record<string, { 가중치; 근거_사료: string[] }>
  안_통하는_것: string[]; 역효과: string[]
  말투: { 정통; 밈 }
  사료_저장소: string[]  // SourceSnippet.id 참조
  승패_대사: { 승리; 역효과_실패; 변사_실패 }
}

SourceSnippet {          // docs/research → RAG
  id: "S-02"; 주제; 내용; 원문; 출처; url; tier: 1|2
}

Verdict {                // AI 출력 (VERDICT_SCHEMA)
  부합도: "탁월"|"정합"|"부분"|"불합치"|"역효과"
  매칭_가치: string | null
  사용_사료: string[]
  시대착오: boolean
  대사: string
}

ResultCard {
  문장: string; 턴수: number; 등급: "S"|"A"|"B"|"C"
  도전문구: string        // 숨은조건 미포함
}
```

## 6. 게임 상태 머신

```
[세션생성] → CONTINUE ──(입력)──> 판정 → 엔진
   CONTINUE ──(gauge ≥ threshold)──────────────> WIN  → 결과카드
   CONTINUE ──(연속 변사 ≥ 3)────────────────────> LOSE → 결과카드
   CONTINUE ──(그 외)──> CONTINUE (turn+1, 게이지 갱신)
   * 조작탐지/시대착오/모름 → 게이지 하락 또는 불변, 상태 CONTINUE 유지
```

## 7. API 명세 (서버리스 프록시)

### POST `/api/session`
```
req  { agentId }
res  { sessionId, gauge, winThreshold, intro: { 대사, 힌트노출 } }
```

### POST `/api/turn`
```
req  { sessionId, input, tone }
res  {
  대사, 부합도, 게이지, 턴, 상태,     // 상태 = CONTINUE|WIN|LOSE
  사료각주: [{ id, 출처, url }],
  시대착오: boolean, 힌트언락?: SourceSnippet
}
err  429/503 → 폴백 응답(모드: "fallback"|"demo")로 동일 스키마 반환
```
- 키(CLAUDE_API_KEY)는 서버에만. 클라이언트 노출 금지. 레이트리밋·일일 상한 집행.

## 8. 비기능 요구

| 구분 | 요구 |
|---|---|
| 성능 | 턴당 AI 호출 1회. 판정 지연 최소화(프롬프트 캐싱, RAG top-k 제한) |
| 비용 | 일일 토큰/요청 상한. 초과 시 폴백. 값은 `config`로 관리 |
| 보안 | 키 서버 보관, 인젝션 규칙 필터, 상태는 엔진 소유(치팅 불가) |
| 접근성 | 로그인 불필요, 모바일 반응형, 정통/밈 토글, 출처 각주 토글 |
| 호환 | 최신 모바일/데스크톱 브라우저. 링크 즉시 플레이 |
| 콘텐츠 | 역사 사실은 1·2티어 사료만. 열린 웹 금지. 품격 유지(비하 금지) |

## 9. 에러 & 폴백 매트릭스

| 상황 | 처리 | 사용자 체감 |
|---|---|---|
| 일일 상한/429 | 사전 생성 응답 풀 | 게임 계속(근사 판정) |
| 타임아웃 | 1회 재시도 → 폴백 | 지연 후 계속 |
| JSON/스키마 위반 | 1회 재시도 → 불합치 중립 대사 | 자연스러운 반응 |
| RAG 빈 결과 | "기록에 없네" | 신뢰성 연출 |
| 완전 장애 | 스크립트 데모(고정 승리) | 흐름은 반드시 체험 |
