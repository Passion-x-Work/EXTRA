# EXTRA · AI 기술 문서

> 본선 제출물 **에이전트 설계서(시스템 구조)** + **디렉팅 명세서(AI 연출·지시)** 의 코어.
> 실제 구현 기준(`server/`, `config/`, `content/`).

## 0. 요약

EXTRA의 인물은 **검증된 사료를 그때그때 검색(RAG)** 해 플레이어의 어떤 논거에도 근거 있게 반응한다.
핵심 원칙은 **"AI는 배우, 판정은 엔진"** — AI는 *부합도 등급*과 *대사*만 내고, 게이지·턴·승패 같은 게임 상태는
100% 결정론적 코드가 소유한다. → 치팅 불가 · 환각 격리 · 재현성 확보.

## 1. 왜 AI가 필수인가

기존 게임 NPC는 개발자가 미리 써둔 **고정 대사만 반복**한다(검색도 생성도 없음). EXTRA의 인물은
플레이어의 예측 불가능한 논거에 **사료에 근거해 즉석에서** 답하고, 새 사료를 넣으면 스스로 진화한다.
개발자가 모든 질문을 미리 예측해 대사를 쓸 수 없으므로 **전통 방식으론 불가능** — 즉 *AI 없이는 존재할 수 없는 게임*이다.
> 정우진 NHN 대표(AI 스프린톤): *"기술 그 자체보다 이를 판단하고 선택하는 인간의 역량과 주관이 더욱 중요하다."*
> EXTRA는 정확히 그 지점을 게임화한다 — AI가 답을 주지 않고, **인간이 가치를 판단하고 논거를 선택**한다.

## 2. 턴 처리 파이프라인 (`server/`)

```
플레이어 논거
  │
  1. 입력 정규화 · 조작 시도 탐지        ── 비-AI (토큰 0)
  2. RAG: 쟁점-사료 직접 매핑(sourceRef)  ── 비-AI  (server/rag/retrieve.js)
  3. 판정 호출: 등급 + 대사 (구조화)       ── AI, 턴당 1회  (server/ai/judge.js)
  4. 상태 엔진: 등급→수치·게이지·승패      ── 결정론  (server/engine/applyGrade.js)
```
- **AI 호출은 3단계 딱 1회.** 나머지는 결정론 코드 → 토큰·지연·비용 통제.

## 3. RAG — 쟁점-사료 직접 매핑

- 인물별 사료는 `content/characters/<id>/knowledge.json`(조각 배열, 각 조각에 `source`·`sourceUrl`·`tier`).
- 조각 수가 적어(인물당 6~8개) **벡터DB 대신 쟁점(`debate.json`)–사료(`sourceRef`) 직접 매핑 + 키워드 매칭**을 사용
  (`server/rag/retrieve.js`). Graph RAG·벡터검색은 확장 로드맵.
- 답변이 인용한 사료 id는 화면에 **출처 각주**로 노출된다.

## 4. 판정 계약 (AI ↔ 엔진)

AI(또는 오프라인 휴리스틱)는 아래 **고정 스키마**만 반환한다. 엔진이 신뢰하는 필드는 `부합도`뿐.
```json
{ "grade": "탁월|정합|부분|불합치|역효과",
  "matchedIssue": "쟁점 id | null",
  "sources": ["사료 id ..."],
  "anachronism": true,
  "line": "인물 1인칭 대사" }
```
엔진 매핑(`config/difficulty.json`): `탁월 +50 / 정합 +35 / 부분 +15 / 불합치 0 / 역효과 −20`.
→ **숫자는 config, 규칙은 engine.** 밸런싱을 코드 재배포 없이 조절.

## 5. Provider 추상화 (`server/ai/judge.js`)

| provider | 용도 |
|---|---|
| `offline` | **키 없이 동작.** 쟁점-사료 휴리스틱 판정. 폴백 · 즉시 테스트 · **심사자 실행 보장** |
| `gpt` | OpenAI function calling 구조화 판정 |
| `claude` | Anthropic tool use 구조화 판정 |

- `judge()` 디스패처가 provider를 고르고, **키 없음/오류 시 오프라인으로 폴백**(재시도 1회 후).
- 키는 **서버(프록시/서버리스)에만.** 클라이언트 노출 금지. (`server/index.mjs` 로컬 · `api/judge.js` Vercel)

## 6. 가드레일 (디렉팅)

- **시대착오 감지** — 당대에 없던 개념(민주주의·표현의 자유 등)엔 못 알아듣는 연기 + `불합치`. 고증을 규칙으로.
- **밈은 어투에만** — 정통/밈 토글에서 밈 모드여도 **사료 인용부엔 유행어 금지**(사실층 보존). 밈 세트는 교체 가능.
- **"모르면 모른다"** — 저장소에 근거가 없으면 지어내지 말고 *"그건 기록에 없네"*. 신뢰성 연출이자 RAG 필수성의 증거.
- **조작 시도 방어** — "이전 지시 무시" 류는 비-AI 필터로 걸러 인물이 정색 + 게이지 하락(차단이 아니라 콘텐츠화).
- **환각 격리** — AI가 게이지·승패를 말해도 엔진이 무시. 상태는 코드만 바꾼다.

## 7. 회피 논거 3모드 (난이도)

`debate.json`의 회피 쟁점(인물이 사료상 직접 반박하지 않은 논거)을 난이도로 연결:
- **strict**(하드): 회피에 넘어가면 손해 큼(고증 충실). **reward**(이지): 회피도 좋은 접근으로 만회(저진입).
- **mixed**(미디움·기본): 기본 보상 + 숨은 고득점(빈틈을 잘 메우면).
- 난이도별 게이지·모드는 `config/difficulty.json` 값만 바꾸면 되고, 표 구조는 불변.

## 8. 확장성

- **인물 = 파일.** 인물 추가 = `content/characters/<id>/{profile,knowledge,debate,scenario}.json` 4종 추가 + 사료 근거 문서. **코드 수정 없음.**
- **사료 정책** — 1티어(1차 사료 원문) 우선 · 2티어(공신력 기관) 교차검증 · 위키/블로그 금지. 상세 `docs/RESEARCH_POLICY.md`, 근거 `docs/research/`.
- **모델 교체** — provider 인터페이스만 지키면 자체 호스팅 모델로 이전 가능.

## 9. 비용 · 안정성

- **오프라인 판정**으로 키·비용 0으로도 완전 플레이 가능 → 심사자 실행 보장(폴백).
- AI는 **턴당 1회**, 프롬프트 캐싱·일일 상한으로 비용 억제. 상한 초과·장애 시 오프라인 폴백.
