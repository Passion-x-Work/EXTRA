# EXTRA · 하네스 엔지니어링 (Harness Engineering)

> "하네스" = Claude(배우)를 감싸 게임으로 만드는 **결정론적 실행 스캐폴드**.
> 본선 제출물 **에이전트 설계서**의 코어. 위치: `server/harness/`.
>
> **제1원칙 — AI는 배우, 판정은 엔진.** Claude는 *부합도 등급*과 *대사*만 낸다.
> 게이지·턴·승패는 코드가 소유한다 → 치팅 불가 · 환각 격리 · 재현성 확보.

---

## 1. 턴 처리 파이프라인 (요청 생명주기)

```
플레이어 발화
  │
  1. 입력 정규화        (공백/길이/이모지 정리)                     ── 비-AI
  2. 조작 시도 탐지     (인젝션 규칙 필터)                          ── 비-AI
  3. RAG 검색           (인물 사료 저장소 top-k)                    ── 비-AI
  4. 프롬프트 조립      (system + 인물 스키마 + 사료 + 히스토리 + 톤) ── 비-AI
  5. Claude 판정 호출   → 구조화 JSON 1회                           ── AI (턴당 1회)
  6. 출력 검증          (스키마 검증 · 실패 시 재시도/폴백)          ── 비-AI
  7. 상태 엔진 적용     (등급→수치, 게이지, 턴, 승패, 등급)          ── 결정론
  8. 렌더링             (대사 + 게이지 + 사료 각주)                  ── 비-AI
```

핵심: **AI 호출은 5단계 딱 1회.** 나머지는 전부 결정론적 코드 → 토큰·지연·비용 통제.

## 2. 턴 핸들러 (의사코드)

```js
// server/harness/handleTurn.js
export async function handleTurn(agent, state, tone, rawInput) {
  const input = normalize(rawInput);

  // 2. 조작 시도 → AI 호출 없이 게임화 처리
  if (detectInjection(input)) {
    return applyGrade(state, "역효과", {
      대사: agent.말투[tone].인젝션_반응, 사용_사료: [], 시대착오: false,
    });
  }

  // 3~5. RAG → 프롬프트 → 판정 (turn 당 1회)
  const snippets = ragSearch(agent.사료_저장소, input, { topK: 3 });
  const messages = buildPrompt({ agent, snippets, history: state.history, tone, input });
  let verdict = await model.judge(messages, { schema: VERDICT_SCHEMA });

  // 6. 출력 검증 (스키마 위반 시 1회 재시도 → 그래도 실패면 안전 폴백)
  verdict = validate(verdict, VERDICT_SCHEMA)
    ?? validate(await model.judge(messages, { schema: VERDICT_SCHEMA }), VERDICT_SCHEMA)
    ?? SAFE_FALLBACK_VERDICT;

  // 7. 결정론 엔진이 상태 갱신 (AI는 여기 관여 못 함)
  return applyGrade(state, verdict.부합도, verdict);
}
```

## 3. 구조화 출력 계약 (AI ↔ 엔진 인터페이스)

```json
// VERDICT_SCHEMA
{ "부합도":  "탁월|정합|부분|불합치|역효과",
  "매칭_가치": "<가치키>|null",
  "사용_사료": ["S-02"],
  "시대착오":  true,
  "대사":      "인물 1인칭 응답(톤 반영)" }
```
- **엔진이 신뢰하는 필드는 `부합도`뿐** (수치 매핑용). 나머지는 연출·표시용.
- 파싱/스키마 실패 → 1회 재시도 → 그래도 실패면 `불합치` + 중립 대사(게임 안 멈춤).

## 4. 상태 엔진 (결정론 · AI 격리)

```js
// web/src/engine/applyGrade.js
const MAP = { 탁월: +50, 정합: +35, 부분: +15, 불합치: 0, 역효과: -20 };

function applyGrade(state, 부합도, verdict) {
  const next = clamp(state.gauge + MAP[부합도], 0, 100);
  const turn = state.turn + 1;
  const status =
    next >= state.승리문턱                       ? "WIN"
    : (verdict.변사 && state.연속변사 >= 3)       ? "LOSE"
    : "CONTINUE";
  return { ...state, gauge: next, turn, status, lastVerdict: verdict };
}
```
- 수치·문턱·페널티는 `config/difficulty.json` 상수 → **밸런싱 = 데이터**(코드 재배포 없이 조절).
- 게이지 초기값·승리문턱이 곧 **난이도 다이얼**(튜토리얼↔고난도).

## 5. RAG 검색

- 저장소 = `agents/<id>.md`의 `사료_저장소`(조각 배열). 데모는 로컬, 확장은 국사편찬위 오픈API.
- 검색: 발화 키워드/의미 매칭 top-k(기본 3). 주입 예산 초과 시 조각 요약본 사용.
- **출처 강제:** 대사가 인용하는 사실은 반드시 `사용_사료`에 든 조각에서만.
- **"모르면 모른다":** 관련 조각이 비면 프롬프트가 *"기록에 없으면 지어내지 말고 없다고 답하라"* 를 강제.

## 6. 프롬프트 조립 (레이어)

| 레이어 | 출처 | 역할 |
|---|---|---|
| system | 하네스 고정 | 역할·규칙·출력 계약·가드레일 |
| 인물 스키마 발췌 | `agents/<id>` | 통하는_가치 / 안_통하는_것 / 역효과 / 말투 |
| 사료 조각 | RAG | 사실 근거(출처 포함) |
| 히스토리 | state | 직전 N턴 대화 |
| 톤 | 토글 | 정통 | 밈 (말투 층만) |
| 발화 | 플레이어 | 이번 턴 논거 |

## 7. 가드레일

- **프롬프트 인젝션:** 비-AI 규칙 필터 1차 → 인물이 정색 + 게이지 하락 연출(차단 아님, 콘텐츠화).
- **밈 격리:** 톤=밈이어도 **사료 인용부엔 유행어 금지**(사실 층 오염 방지). 밈 세트는 `config/memes.json`.
- **시대착오:** 당대에 없던 개념 → 못 알아듣는 연기 + `불합치/역효과`(고증을 규칙으로).
- **품격:** 친근·재치 OK, 비하·조롱 NO(교육·문체부 명분).
- **환각 격리:** 상태는 엔진 소유. AI가 "게이지 올랐다" 따위를 말해도 엔진이 무시.

## 8. 폴백 & 데모 모드 (탈락 방지 · 필수)

우선순위로 강등하며 항상 응답을 보장:
1. **정상:** Claude 실시간 판정.
2. **일일 상한/429/타임아웃:** `server/fallback/` **사전 생성 응답 풀**(인물별·등급별 대표 대사)로 근사 판정.
3. **완전 장애:** 스크립티드 데모 시나리오(고정 승리 루트)로 심사자가 흐름은 반드시 체험.

> 이 폴백 설계를 문서에 명시해 **감점이 아닌 가점 요소로 전환**한다.

## 9. 비용 · 토큰 예산

- **턴당 AI 호출 1회** 고정. RAG top-k·히스토리 N턴으로 컨텍스트 상한.
- **프롬프트 캐싱:** system + 인물 스키마 등 고정 프리픽스 캐시로 반복 비용 절감.
- **일일 상한:** 프록시에서 요청 수·토큰 상한 집행. 초과 시 §8 폴백.
- **모델 티어:** 판정은 경량 모델로도 충분한지 실험(품질↔비용). 값은 밸런싱 데이터로 관리.

## 10. 모델 추상화

```js
// server/harness/model.js — 판정기 교체 가능 인터페이스
export const model = {
  judge: (messages, opts) => provider.complete(messages, opts), // 클로드 → (확장) 자체 호스팅
};
```
- Claude 확정. 인터페이스만 지키면 모델 교체·이전 경로 확보(심사 '확장성' 대응).

## 11. 에러 · 재시도

| 상황 | 처리 |
|---|---|
| 429 / 상한 | 즉시 §8-2 폴백 |
| 타임아웃 | 1회 재시도 → 실패 시 폴백 |
| JSON/스키마 위반 | 1회 재시도 → 실패 시 `불합치` 중립 대사 |
| RAG 빈 결과 | "기록에 없네" 경로(정상 연출) |

## 12. 관측 · 로깅

- 판정 **등급 분포**·턴 수·승률을 로깅 → 밸런싱 데이터(난이도 상수 조정 근거).
- 개인정보·발화 원문 저장 최소화(로그인 없는 게임).

## 13. 테스트 (골든 케이스)

- 인물별 **승리 / 역효과 / 시대착오 / 모름(기록에 없음)** 각 1케이스 이상.
- **결정론 회귀:** 같은 입력·같은 등급 → 항상 같은 게이지 결과(엔진).
- **가드레일:** 대표 인젝션 문구 세트가 전부 '정색+하락'으로 처리되는지.
- **폴백:** 상한 강제 발동 시 게임이 끝까지 진행되는지.
