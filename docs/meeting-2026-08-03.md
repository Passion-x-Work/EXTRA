## D. 기능 / 설계 확인 포인트 (⚠️ 확인 필요 · 💡제안)

| 항목 | 제안 | 코멘트 |
|---|---|---|
| **Claude 호출 횟수** | 정상 1회 + 검증 실패 시 예외 1회 + 폴백, **예외는 로그** | ✅ "턴당 1회"는 **정상경로 기준**으로 재정의. 재시도=예외로 명시하면 원칙 안 깨짐 |
| **applyGrade에 게이지·3모드 반영** | `debate.json`의 `avoidanceMode`(strict/reward/mixed)를 엔진이 읽어 회피 논거 처리(0 / 숨은 고득점) | 상세는 아래 |
| **RAG 단순화** | 조각 8개뿐 → top-k 벡터검색 대신 **쟁점-사료 직접 매핑(`sourceRef`)**. Graph RAG는 확장 로드맵으로만 | ✅ 8조각이면 벡터DB 오버킬. 직접 매핑이 정답 |
| **대화 기억 N턴** | 값 확정 + **config에 두기.** 논거 재탕·말바꾸기 감지는 MVP에선 **N 넉넉히**, 정교한 감지는 후순위 | ✅ 동의. 감지는 본선용 |

**회피 논거 3모드 상세**
- **strict**: 회피에 넘어가면 게이지 손해 큼. 고증 충실·고난도, 대신 답답할 수 있음.
- **reward**: 회피 상황도 다른 좋은 접근으로 만회 가능. 재미·도파민, 진입장벽 낮음.
- **mixed**: 기본 보상 + 명백한 회피엔 페널티. **현재 `debate.json` 기본값.**
- ⚠️ **유나님께 물어볼 것**: 3모드 개념 공유 → **MVP는 어느 모드?** (유나님 성향상 reward/mixed 선호 예상) → 셋 다 테스트할지 mixed로 시작할지.

**applyGrade 반영 방법 (반영한다면)**
- 게이지 수치(시작 40 / 승리 100 / 패배 0)와 모드별 페널티·보상 강도 = **`config/difficulty.json`에** 둠.
- **`applyGrade`(engine)는 config 값을 읽어 판정만** — 숫자는 config, 규칙은 engine으로 분리.
- → 3모드 각각 테스트가 **config 값만 바꿔 바로 가능**, 표 구조도 안 바뀜.
- ⚠️ **유나님께 물어볼 것**: "applyGrade가 `difficulty.json`에서 값 읽는 구조로 생각했는지, engine에 직접 넣을 생각이었는지."
