# EXTRA

엑스트라(EXTRA) — 역사에 끼어든 단역이 되어 실존 인물을 설득하는 게임
NHN AI 해커톤 · 팀 덕업일치(Passion x Work)

> 🎮 **바로 플레이: https://extra-4ki9.onrender.com**
> (무료 호스팅 특성상 첫 접속 시 로딩이 30초~1분 걸릴 수 있습니다)

## 소개

검증된 사료로 구현된 실존 역사 인물(AI 에이전트)과 대화하며 설득하는 교육형 웹게임입니다.
플레이어는 역사에 끼어든 단역이 되어, 결정적 순간의 인물을 만나 대화로 설득합니다.

핵심 원칙: **사실은 사료, 말투는 자유.**
인물의 답변은 검증된 사료에 근거하며 환각(사실 왜곡)을 만들지 않습니다.

두 가지 방향의 플레이가 있습니다.

- **정방향(세종·반 고흐)** — 내가 인물을 설득한다. 좋은 논거로 신념 게이지를 100까지.
- **역방향(미야모토)** — AI(가상의 동료 하루·쿠로다)가 나를 유혹·압박한다.
  가짜 명언까지 섞어 던지는 설득을 반박하며 거장의 철학을 지켜낸다.

## 실행 방법

Node.js 18 이상과 npm이 필요합니다.

```bash
git clone <repository-url>
cd EXTRA
npm install
npm run dev
```

브라우저에서 `http://localhost:5173` 으로 접속합니다.

### AI 판정 모드 (선택)

**API 키가 없어도 게임은 완전히 플레이됩니다.** 키가 없으면 오프라인 휴리스틱
판정으로 자동 폴백하며, 게임 루프·신념게이지·승패 판정이 모두 정상 동작합니다.

실제 AI 판정(제출·시연 기본 = **GPT**)을 쓰려면 프로젝트 루트에 `.env`를 만들고 키를 넣습니다.
(Claude는 선택 대체 — 변수명은 `CLAUDE_API_KEY`, `ANTHROPIC_API_KEY` 아님 주의)

```
AI_PROVIDER=gpt
OPENAI_API_KEY=sk-...
# (선택) CLAUDE_API_KEY=sk-ant-...
```

그리고 판정 프록시 서버를 함께 실행합니다. (미실행 시 `/api/*`가 실패해
오프라인 판정으로 자동 폴백됩니다)

```bash
npm run server   # 판정 프록시 :8787
npm run dev      # 프론트 :5173 (별도 터미널)
```

### 배포 (Render 등 단일 서버)

`server/index.mjs`가 판정 API와 빌드된 프론트(dist/)를 함께 서빙합니다.

```bash
npm run build    # dist/ 생성
npm start        # :8787 하나로 게임 + API 모두 서빙
```

Render 설정: Build = `npm install && npm run build` · Start = `node server/index.mjs`
· 환경변수는 대시보드에 등록. 자세한 내용은 [docs/DEPLOY.md](docs/DEPLOY.md) 참조.

두 판정 모드의 차이는 다음과 같습니다.

| | 오프라인 판정 | AI 판정 (GPT/Claude) |
|---|---|---|
| API 키 | 불필요 | 필요 |
| 판정 방식 | 키워드 매칭 휴리스틱 | 논거의 내용·맥락 이해 |
| 회피 / 정면응답 구분 | 제한적 | 가능 |
| 인물 응답 | 정형화된 응답 | 매 턴 생성 |
| 용도 | 실행 확인 · 자동 테스트 · 폴백 | 실제 게임 경험 |

### 테스트

```bash
npm test                        # 정방향 엔진 스모크 (오프라인·결정론)
node test/miyamoto-smoke.mjs    # 역설득 엔진 스모크 (멀티턴·부분점수 포함)
node test/balance-qa.mjs        # 오프라인 판정 정확도 QA
```

모두 API 키 없이 실행됩니다.

## 게임 구성

- **조선 · 세종대왕** — 완전 구현 (1444년 훈민정음 반대 상소 국면) · 메인 시나리오
- **유럽 · 반 고흐** — 구현 (그리기를 포기하려는 순간의 설득) · 퍼블릭 도메인 예술 IP
- **번외 · 미야모토** — 역설득 모드. 가상의 동료(하루·쿠로다)의 유혹·가짜 명언을
  반박해 게임 디자인 철학을 지킨다 (생존 인물 보호: 대사 창작 없음, 철학은 출처
  기반 패러프레이즈)

## 게임 흐름과 주요 시스템

**흐름**: 고지도(무한 스크롤·핀 선택) → 인트로 → 대화(신념 게이지) → 결과 카드

- **난이도 3종**(이지/미디움/하드): 시작 게이지 보정 + 회피 논거 처리 모드 차등
- **힌트 시스템**: 난이도별 예산(이지3/미디움2/하드1), 자동(연속 실패)+수동(💡) 병행.
  클리어 시 다음 난이도용 보너스 힌트 지급
- **카드 수집(도감)**
  - 📜 사료 카드 — 판정 근거로 만난 사료 (뒤집으면 원문·출처)
  - 💬 나의 논거 카드 — 탁월/정합을 받은 내 논거를 축별 저장, 대화 중 꺼내 쓰기
  - 🃏 철학 카드 — 역모드 방어 성공 시 획득(브론즈/실버/골드, best-rebuttal 갱신)
- **밈 말투 토글**: 정통 사극체 ↔ 현대 밈 톤 전환(사료 인용부는 유행어 금지),
  캐릭터 일러스트 시리즈도 함께 교체
- **연출**: 게이지 연동 배경·표정(Phase) 전환, 난이도별 승리 댄스 클립,
  패배 시 인물의 도발 대사+클립("킹받는 엔딩"), 결과 공유 카드(PNG)
- **베끼기 응징**: 사료 원문을 그대로 옮기면 되돌리기 페널티 — 자기 언어로 설득해야 함
- **진행 저장**: 판 중간에 나가도 이어하기 지원(localStorage)

## 기술 구성

- 반응형 웹(web) ↔ 게임 로직·판정 프록시(server) ↔ GPT/Claude API
- 서버 역할: 사료 검색(RAG) · 인물 프롬프트 · 판정 · (배포 시) 정적 서빙
- 게임 상태(게이지·턴·승패)는 클라이언트 엔진이 소유, 서버는 판정만
- 인물 데이터는 JSON으로 분리 → 인물 추가는 폴더 복사만으로 확장

### 판정 파이프라인

```
입력 정규화 → 인젝션 탐지 → 쟁점·사료 검색 → 판정(턴당 1회)
  → 검증 실패 시 재시도 1회 → 폴백 → 등급 산출 → 게이지 반영
```

판정 결과는 탁월·정합·부분·불합치·역효과 5단계 등급으로 나오고, 등급별 게이지
변동량은 `config/difficulty.json`에 정의됩니다.

숫자는 설정 파일에, 규칙은 엔진에 둡니다. 게이지 시작값·승리선·힌트 예산 같은
상수는 모두 `config/difficulty.json`에 있고, 엔진(`applyGrade.js` ·
`miyamotoEngine.js`)은 그 값을 읽어 판정만 수행합니다. 밸런스 조정이 코드 수정
없이 가능합니다.

역설득(미야모토)은 멀티턴 공방으로 진행됩니다: 중간 공방은 소폭(1/3), 최종
공방에 본 점수가 들어가며, 동조하면 화자가 "정말 넘어온 거냐"고 한 번 더
확인합니다.

사료 조각 규모가 작은 현 단계에서는 벡터 검색 대신 쟁점–사료 직접 매핑
(`sourceRef`)을 사용합니다. Graph RAG는 이후 로드맵입니다.

자세한 내용은 [docs/하네스-엔지니어링.md](docs/하네스-엔지니어링.md) 참조.

## 사료 관리

모든 인물 데이터는 검증된 사료에 근거하며, 출처 기준과 갱신 정책을 별도로
관리합니다. 자세한 내용은 [docs/RESEARCH_POLICY.md](docs/RESEARCH_POLICY.md) 참조.

미야모토의 논거 중 하나(arg-04)는 **의도된 가짜(오귀속) 명언**입니다 — "출처를
의심하라"는 게임의 교육 목표 그 자체이며, 데이터에 `trap_misattributed`로
명시되어 있습니다.

## 폴더 구조

    EXTRA/
    ├─ web/       # 프론트엔드 (UI, 화면 흐름)
    │  ├─ index.html
    │  ├─ public/ # Assets/ — 인물 일러스트(webp) · 승리 클립(webm/mp4) · 고지도
    │  └─ src/    # app.js(게임 루프·역모드·도감) · style.css(한지풍 디자인)
    ├─ server/    # 게임 로직 + 판정 프록시(index.mjs, 배포 시 정적 서빙 겸용)
    │  ├─ ai/     # judge.js — 논거 판정 (GPT/Claude + 오프라인 폴백)
    │  ├─ engine/ # applyGrade.js(정방향) · miyamotoEngine.js(역설득 멀티턴)
    │  └─ rag/    # retrieve.js — 쟁점·사료 검색
    ├─ api/       # Vercel 서버리스 판정 함수 (judge.js · judgeReverse.js)
    ├─ config/    # difficulty.json — 게이지·난이도·힌트 예산·등급 밴드
    ├─ content/   # 인물별 데이터 (sejong·vangogh: profile/knowledge/debate/scenario,
    │             #                miyamoto: cards/scenario · hokusai: 차기 공개 예약)
    ├─ agents/    # 인물별 에이전트 설계 문서
    ├─ assets-original/ # 원본 에셋(PNG·영상) — 게임은 web/public의 webp/webm 사용
    ├─ docs/      # 프로젝트 문서
    └─ test/      # 오프라인 엔드투엔드 테스트 4종

인물 데이터는 `content/characters/` 아래에 인물별로 격리되어 있고, 엔진은 특정
인물을 알지 못합니다. 새 인물은 JSON 추가만으로 편입됩니다(정방향 4종 또는
역설득 cards+scenario).

설계 의도는 `agents/*.md`(사람이 읽는 문서)에, 실행에 쓰이는 값은
`content/**/*.json`(엔진이 읽는 데이터)에 둡니다. JSON 키는 한글로 통일하고
파일명만 영어를 사용합니다.

## 현재 상태

세 시나리오(세종·반 고흐·미야모토 역설득)가 처음부터 끝까지 동작합니다.
고지도에서 핀을 골라 진입하고, 대화·판정·카드 수집·승리 클립·결과 공유까지
전체 루프가 완성되어 있습니다. 호쿠사이는 차기 공개용으로 데이터만 보존
상태입니다.
